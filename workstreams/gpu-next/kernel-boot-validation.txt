Disposable allocator-kernel boot validation

Purpose: boot the actual allocator-corrected kernel before synthetic IRQ lifetime
validation. This is not Intel GPU execution and does not validate physical IRQs.

Source: isolated gpu/n100-vector-exhaustion commit ee4f34defcd6aca262814ffdbc72cdb8f8af64b3.
Build: pinned CI toolchain image recorded in testing/kernel-vector-build-001/provenance.json.
IMPORTANT: jam kernel_x86_64 links a kernel but does not stamp its runtime revision.
Use jam '<revisioned>kernel_x86_64' for the actual boot artifact (kernel/Jamfile178).
The stamp is git-f01e0b78-irq-vector-validation, an explicit test label, not a release.
Stamped SHA256:e2fbc2f00d8bb4161dc994ed0950a96f4793861bd7a2a9173b8d699c9885bc21.

Loader: loader.cpp opens system/kernel_x86_64 through BootVolume.SystemDirectory.
That directory is packagefs from the selected system package, chosen via
system/packages/administrative/activated-packages. Non-packaged kernel override
is not established by the driver add-on lookup path. Do not assume it works.

Procedure implemented (private scripts and complete logs retained):
1. Fresh reflink/sparse copy of preserved installation/private/gpu-hdmi-build-040/disk.img.
2. Boot read-only inventory under host-config/haiku-vm/build locks. Capture uname,
activated-packages, selected system package and guest kernel; compare source/destination hashes.
Selected package:haiku-r1~beta6_hrev60072_518-1-x86_64.hpkg.
Original package SHA256:b04e3ba74d3c9d217f8918833e48809cd8ac0eef3730e4de5f7cc51b8e883955.
Original kernel SHA256:66753cb36a1481790dbf55a564e8632fdcb7534fdacbb6f5999432ea196de4f6.
3. On a package COPY, built package tool add -f -1 replaces only kernel_x86_64.
Use the revisioned build directory as input and the writable generic build attribute
store; copying the file alone loses attributes held outside Linux file xattrs.
4. Extract original/candidate, compare all6204 paths: modes, regular-file SHA256,
symlink targets and package metadata. Only kernel entry may differ. Inspect TOC
attribute descriptors; all non-kernel entries retained, kernel build attributes present.
This file comparison is not a separate byte-hash comparison of every attribute value.
5. Do NOT replace an active live system package: package daemon may ignore same-name
created events or cancel removal, and system packages are special during activation.
6. Build '<build>bfs_shell'. With VM STOPPED and canonical locks held, use explicit
GPT BFS byte bounds (from sfdisk JSON, not guessed) and /myfs/system/packages/path.
Read original package through BFS and verify hash. Copy candidate at same filename.
Unmount, remount and read it back; compare entire hpkg SHA256 and activated list.
Only disposable image is mounted; no block device or physical target passed to tool.
7. Boot bounded with serial/QMP, verify unique KERNEL SERIAL revision, guest-visible kernel
and selected package hashes, preserve logs and require clean shutdown. Uname uses
libroot's own revision (uname.c:41), not the kernel revision; combine offline boot-input and guest hash evidence.
