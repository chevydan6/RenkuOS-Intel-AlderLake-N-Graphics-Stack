## Stock UEFI log interpretation for shared testing

The power agent reported a warm-reboot hang using the stock framebuffer driver;
no GPU project patches were installed. Static inspection of the pinned source
found that `Screen::SetBestMode()` logs `timing.h_total/v_total` in its fallback
message, rather than visible dimensions. Its parenthesized value is `color_space`:
`B_RGB32` is 0x0008. Consequently `Use 2832x2119 (8)` does not establish a visible
2832x2119 mode or 8-bit pixels. The framebuffer accelerant only accepts the
firmware's current virtual width/height and color space. This correction was sent
to the power agent; it does not explain or resolve the reported reboot hang.

Bundle `renku-014` compiled and linked the full Intel kernel driver and
accelerant. Its test build then rejected empty aggregate initialization of
`DeviceType` in the gating harness. Explicit device-type initialization fixes
that test fixture; bundle `renku-015` is the fresh full rerun. Production source
patches did not change in response to this harness error.
