# A37: initial Gen12 BCS0 context-image construction

Implemented offline in `workstreams/gpu-next/IntelN100ContextImage.h`.
715 host ASan/UBSan and715 native VM cases passed, including full16KiB byte
comparisons against extracted pinned Linux routines. Hardware use is pending.

## Fixed profile and inputs

N1008086:46d1/revision0, primary GT/GSI offset0, BCS0/Gen12.0, four-level PPGTT,
fresh context without a saved default state. Caller provides context/ring GGTT
addresses, PML4 DMA address, ring size and a nonzero initial tail. These are
distinct address domains; the helper validates arithmetic, not ownership or
translation. It emits into caller-owned unpublished CPU memory only.

Before writes: exact16KiB output capacity, nonnull/aligned/nonwrapping CPU
range; page-aligned full16KiB context interval below4GiB; distinct nonoverlapping
ring interval below4GiB; power-of-two ring size4KiB..2MiB; qword-aligned tail
8..size-64; aligned39-bit PML4 DMA page; exact identity/revision. Initial head0
and one-cacheline free space avoid wrap/empty-ring ambiguity. Input is copied
before zeroing output. Every rejection leaves output unchanged.

## Layout and initialized fields

| Byte interval | Contents |
| --- | --- |
| 0x0000..0x0fff | Private per-process HWSP, initially zero |
| 0x1000..0x1fff | Gen12 XCS initial register image |
| 0x2000..0x2fff | Indirect workaround commands, storage and separate predicate helper |
| 0x3000..0x3fff | Separate per-context batch; initial BBE then zero padding |

The engine CSB HWSP from A36 is a separate allocation, not page0 of this image.

Register-image dword indices (relative to page1):

* 1: posted/CS-relative LRI13, with register offsets from `gen12_xcs_offsets`.
* 0x21: posted/CS-relative LRI9, following five NOOP slots.
* 0x34: initial BBE with Gen11+ bit0.
* 3: `0x00090009`, masked synchronous-switch inhibit + initial restore inhibit.
* 5/7/9/11: head0, caller tail, ring GGTT start, `(ringBytes-4096)|RING_VALID`.
* 0x13: per-context batch GGTT start with FORCE/VALID.
* 0x15/0x17: indirect GGTT start with two-cacheline length, offset `0xd<<6`.
* 0x23: initial timestamp0;0x31/0x33: PML4 upper/lower dwords (no leaf flags).
* 0x61: saved MI_MODE `0x01000000`, masked **STOP_RING bit8** clear.
* 0x75: saved GPR0 value0, used by scratch restore. Remaining bytes initially zero.

Indirect span: load saved timestamp to GPR0, write timestamp twice, restore
GPR0 from its saved field, issue BCS AUX invalidation at0x4248 and register-poll
wait for clear, then NOOP-pad22 dwords to128 bytes. This GPU semaphore wait is
source-required AUX register polling, not a CPU-cleared request semaphore.
Hardware access to this register and hang recovery remain to validate.

The source also populates an11-dword predicate-disable helper at indirect-page
offset2048 and reserves its result at offset4088. It is outside the128-byte
indirect span and is not linked by this builder. The separate per-context batch
is only BBE on this profile: fast-color workaround applies to IP12.55..12.71,
not N100's12.0.

## Independent byte oracle and findings

`tests/context-image-host.py` rejects incorrect hashes for the source routines
and headers it compiles, removes header include dependencies, and extracts the
original offset decoder/table, saved-field helpers and workaround emitters.
The only code-token adaptation is C's `->class` to C++'s `->engine_class`.
Its wrapper supplies the fixed N100 profile and simple address/backing shims;
unsupported DG2/fast-color branches assert if invoked. Signed-comparison warnings
are suppressed only around extracted Linux code; candidate warnings remain errors.
This is a source-derived oracle, not an independent hardware specification.

The first comparison exposed a candidate mask error: saved MI_MODE used bit9
(MODE_IDLE) instead of bit8 (STOP_RING). It was corrected to0x01000000 before
any native/hardware deployment. Final715 host/native cases pass:681 full16KiB
comparisons and34 rejection/guard checks. Tests include all10 supported ring
sizes, boundary addresses/roots,512 deterministic varied cases, nonoverlap/adjacency,
invalid identity/revision/capacity/alignment/overflow/tails and output guards.

## Remaining integration

These bytes do not establish a valid DMA mapping, programmed PAT/MOCS, memory
visibility, TLB state, owned engine/power state, complete stepping workarounds,
or retirement. Integrate context/ring/status/result/PPGTT ownership first, then
review engine initialization and publication under a retained execution record.
Keep ELSQ load absent until those prerequisites and bounded recovery are ready.
