`get_module` rejects caller-owned sModulesLock recursion before entry allocation, lookup, image search or reference mutation. Its own depth-one reservation pins the target metadata, image and per-thread entry. Child get_module and INIT std_ops execute after exactly one unlock; the lock is reacquired before validation, dependency publication or public reference publication. Failure preserves acquired prefixes and transition/image custody. UNINIT remains conservative and locked.

Search/load boundary: module.cpp get_module -> search_module -> check_module_image -> get_module_image -> load_module_image -> elf.cpp load_kernel_add_on. get_module_image takes an additional RecursiveLocker; create_module also temporarily recurses around hash insertion. These scopes finish before get_module calls init_module, so reservation depth returns to one. load_module_image asserts lock ownership and invokes the ELF loader while owned; it does not call module INIT. The pinned ELF loader uses sImageLoadMutex and VFS entry points. VFS can reach module acquisition (vfs.cpp load_file_system/get_module); reentry while this thread owns sModulesLock now returns B_BUSY before mutation. This deliberately fails closed; it does not promise filesystem autoload progress under the loader. No caller-owned acquisitions are silently dropped, and no VFS/ELF unlock conversion is in scope.

Production-function host coverage: run.py extracts actual composed module functions and real ACPI root/core std_ops. concurrent.cpp uses two OS threads, a real recursive mutex, thread-local ownership/depth and distinct thread identities. Controlled pauses inside dependency INIT and parent INIT allow a competing thread to prove pre-owned rejection, same-target/public-release busy without consumed references, Building-image busy without publication, unrelated progress and complete shared dependency leases after Building ends. Context association and final pin/ref counts are checked. Existing fixtures cover cycles, allocation failures, partial prefixes, nested ACPI, stale transition/context identities, no replay and search-pin balance.

Limits: search_module and kernel infrastructure remain host substitutes; the boundary above is source audited, not native loader execution. No full kernel build, VM, hardware, GPU execution, deployment or milestone acceptance is claimed. ASAN_OPTIONS=detect_leaks=0 disables LeakSanitizer because of the known traced-process restriction.
