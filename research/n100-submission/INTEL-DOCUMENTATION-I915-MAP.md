# N100 GPU documentation and i915 map

Research snapshot 2026-11-14. Documentation only; no implementation or hardware action.
Linux reference revision throughout: [028ef9c96e96197026887c0f092424679298aae8](https://github.com/torvalds/linux/tree/028ef9c96e96197026887c0f092424679298aae8/drivers/gpu/drm/i915). Line links below are immutable at that revision.

## Existing project research checked first

[Architecture](../../INTEL_N100_GPU_ARCHITECTURE.md), [submission research](../../GPU_COMMAND_SUBMISSION_RESEARCH.md), [submission design](DESIGN.md), [context image](CONTEXT-IMAGE-DESIGN.md), [context status](CONTEXT-STATUS-DESIGN.md), and [reset](BCS-RESET-DESIGN.md) already map this Linux revision. Their source-derived proposals and prior physical observations must not be conflated with Intel specifications. In particular, the reset note records a successful reset-only trial and an earlier unexplained safety failure; neither establishes command execution. This note adds a source hierarchy and a navigable map, not a new hardware validation.

## Intel documents and applicability

* **N100-specific:** [Intel N100 product specifications](https://www.intel.com/content/www/us/en/products/sku/231803/intel-processor-n100-6m-cache-up-to-3-40-ghz/specifications.html), GPU Specifications and Essentials: Alder Lake-N, UHD Graphics, 24 EUs, graphics device ID 46D1. Live product page, no document revision stated.
* **N-series:** Intel Processor and Intel Core i3 N-Series Datasheet Volume 1, document **759603 revision 001, January 2023**, [Intel-authored PDF mirror](https://dl.namtso.com/products/a10/a10-n305/datasheets/intel-processpr-and-intel-core-i3-n-series-datasheet.pdf#page=30), section 2.3, tables 6–7: N100 host ID 461C; 0+4, N0, 24-EU graphics ID 46D1. The host ID and GPU ID are different devices. Section 1.11 lists Volume 2 as document 759604. Intel's [document guidance](https://community.intel.com/t/datasheet-for-intel-atom-processors-x7000e-series/121612/2) identifies 759603 and says some EDS material requires Premier access.
* **Related architecture, not N100 authority:** [Intel Iris Xe MAX DG1 open-source PRM, Volume 8](https://www.x.org/docs/intel/DG1/intel-gfx-prm-osrc-dg1-vol08-command_stream_programming.pdf), document reference **IHD-OS-DG1-Vol 8-2.21**. See “Context Submission”, “Logical Ring Context”, “Context Status”, and “Context Status Buffer”. It describes descriptors, global-memory context state and status reporting for DG1. Its ELSP discussion must not be used to replace ADL-N ELSQ behavior. This is a useful conceptual comparison, not proof of N100 offsets, field encodings, workarounds or reset protocol.
* Intel's [Graphics for Linux PRM catalog, document 772631](https://cdrdv2-public.intel.com/772631/graphics-for-linux_developer-reference_1.0-772629-772631.pdf) lists older platform manuals; the accessible catalog text did not yield an Alder Lake entry. A publicly accessible N100-specific GPU command-stream PRM was **not located** in this search. The code map below is Linux implementation evidence, not an independent Intel PRM cross-check. Obtain the applicable Intel ADL-N graphics programming documentation and revision before claiming register-level specification verification.

## Linux mapping: N100 selection versus shared implementation

ADL-N IDs select [adl_p_info](https://github.com/torvalds/linux/blob/028ef9c96e96197026887c0f092424679298aae8/drivers/gpu/drm/i915/i915_pci.c#L681) via [PCI match](https://github.com/torvalds/linux/blob/028ef9c96e96197026887c0f092424679298aae8/drivers/gpu/drm/i915/i915_pci.c#L862). The platform table includes BCS0, 48-bit GPU PPGTT and 39-bit DMA mask, and inherits [Gen11 features](https://github.com/torvalds/linux/blob/028ef9c96e96197026887c0f092424679298aae8/drivers/gpu/drm/i915/i915_pci.c#L603), including ELSQ and noncoherent GGTT. These are driver configuration, not proof of live fuse state, ownership, or DMA/IOMMU mapping. ADL-N firmware selection has a distinct [ADL-S exception](https://github.com/torvalds/linux/blob/028ef9c96e96197026887c0f092424679298aae8/drivers/gpu/drm/i915/gt/uc/intel_uc_fw.c#L300); shared ADL-P device info does not imply identical firmware selection.

## Remaining evidence gaps

An ADL-N-specific Intel PRM and applicable stepping errata remain unverified for ELSQ, context size/fields, CSB, reset, PAT/MOCS and masked MMIO semantics. The DG1 manual cannot close these gaps. Linux behavior is valuable implementation evidence but is conditional on its initialization, scheduling, power, memory and workaround infrastructure. No new hardware state or physical claim follows from this documentation update.
