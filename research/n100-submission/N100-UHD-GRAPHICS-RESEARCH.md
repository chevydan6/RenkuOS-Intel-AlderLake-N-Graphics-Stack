# Intel N100 UHD Graphics: architecture and capabilities

Research snapshot 2026-11-14. Documentation research only; no hardware or implementation changes. This extends [Intel documentation and i915 map](INTEL-DOCUMENTATION-I915-MAP.md) and the existing [architecture research](../../INTEL_N100_GPU_ARCHITECTURE.md).

## Identity and boundaries

Intel calls the N100's integrated GPU **Intel UHD Graphics**, with 24 execution units, device ID 8086:46d1, and up to 750 MHz graphics dynamic frequency. The processor is Alder Lake-N. Intel lists one memory channel and DDR4-3200, DDR5-4800 or LPDDR5-4800 options; actual system configuration affects available bandwidth. The 6 W TDP is for the processor, not a dedicated GPU power budget. [Intel N100 specifications, Essentials, Memory Specifications and GPU Specifications](https://www.intel.com/content/www/us/en/products/sku/231803/intel-processor-n100-6m-cache-up-to-3-40-ghz/specifications.html) (live page, no revision stated).

Intel's **Processor and Core i3 N-Series Datasheet, Volume 1, document 759603 revision 001, January 2023**, [section 2.3, tables 6 and 7](https://dl.namtso.com/products/a10/a10-n305/datasheets/intel-processpr-and-intel-core-i3-n-series-datasheet.pdf#page=30) gives N100 host ID 461c and 0+4 N0 24-EU graphics ID 46d1. [Section 22.1, page 193](https://dl.namtso.com/products/a10/a10-n305/datasheets/intel-processpr-and-intel-core-i3-n-series-datasheet.pdf#page=193) explicitly identifies Xe graphics architecture and distinguishes render/geometry, media and display; up to 32 EUs is a *family* maximum, not the N100's count. Intel's [compute runtime device table](https://github.com/intel/compute-runtime/blob/master/shared/source/dll/devices/devices_base.inl) places 46d1 under SUPPORT_ADLN within SUPPORT_GEN12LP (moving upstream source, accessed 2026-11-14). Thus Gen12LP/Xe-LP is supported by Intel's software classification; do not confuse it with a discrete Arc GPU or infer identical capabilities from another UHD SKU.

## Display, render and media

Intel's N100 product page lists eDP 1.4b, DP 1.4, HDMI 2.1 and MIPI-DSI 1.3, a maximum of three displays, and 4096×2160 at 60 Hz for HDMI and DP. Actual exposed ports and modes depend on the system, firmware, display and software. Intel lists DirectX 12.1, OpenGL 4.6, OpenCL 3.0 and Quick Sync; those are platform capabilities with suitable software, not claims about existing RenkuOS support. [Intel N100 GPU Specifications](https://www.intel.com/content/www/us/en/products/sku/231803/intel-processor-n100-6m-cache-up-to-3-40-ghz/specifications.html).

N-series datasheet **section 22.1.1.1 and table 84**, pages 193–194, lists hardware decode for AVC, HEVC, VP9, JPEG and AV1; **section 22.1.1.2 and table 85**, pages 194–195, describes hardware encoding for AVC, HEVC, VP9 and JPEG, with MPEG-2 listed in its encoder table. Consult each table for profiles, bit depth, resolution and rate; no AV1 encode claim follows. [Datasheet graphics chapter](https://dl.namtso.com/products/a10/a10-n305/datasheets/intel-processpr-and-intel-core-i3-n-series-datasheet.pdf#page=193). Intel's [N-series launch presentation](https://download.intel.com/newsroom/2023/client-computing/Intel-N-series-Processors-Media_Presentation.pdf) corroborates AV1 decode and 10-bit HEVC/VP9 encode/decode. Family-level media claims still depend on the specific device, firmware and driver stack.

The display engine scanning out a framebuffer, the copy engine executing a command, 3D shader execution and media decode are separate milestones. A working desktop is not evidence that BCS submission, OpenGL or media acceleration works. A BCS immediate store would establish command-streamer execution, not EU shader execution or 3D rendering.

## Intel graphics manuals: useful shared reference, not ADL-N specification

Correction/extension to the prior map: Intel's catalog includes a complete **Tiger Lake Iris Xe and UHD Graphics PRM**, not just the DG1 material. It is still a different platform; use it for comparisons and corroboration, not as definitive Alder Lake-N register or stepping documentation.

* [Tiger Lake Volume 8: Command Stream Programming](https://cdrdv2.intel.com/v1/dl/getcontent/703062), **IHD-OS-TGL-Vol 8-12.21, December 2021, revision 1.0**. “Scheduling and Execlists”, printed pages 2–9, describes logical context addresses, descriptors, directly mapped SQ entries, Load and status reporting; “Context Management”, page 43, and “Producer-Consumer Data ordering”, page 53, are also relevant. Printed page 3 explicitly describes both ELSP and directly MMIO-mapped submission queue entries followed by Load. Compare with the pinned i915 ADL-N path before drawing a target-specific conclusion.
* [Tiger Lake Volume 7: Memory Cache](https://cdrdv2.intel.com/v1/dl/getcontent/703061) and [Volume 10: Copy Engine](https://cdrdv2.intel.com/v1/dl/getcontent/705824) are relevant to cache policy and BCS concepts. [Intel Tiger Lake PRM index](https://www.intel.com/content/www/us/en/docs/graphics-for-linux/developer-reference/1-0/tiger-lake.html) also links register, memory views, GPU overview, media, display and workaround volumes. Verify each volume's own title-page revision and applicability.
* Intel's [PRM support page](https://www.intel.com/content/www/us/en/support/articles/000101642/graphics.html) points to the catalog. This research did not locate a public ADL-N-specific graphics command-stream PRM; the N-series datasheet chapter is authoritative for family capabilities but does not establish the detailed submission and reset programming sequence.

## Implications for native adaptation

The project’s pinned i915 source map covers device selection, GT/BCS initialization, logical contexts, ELSQ, CSB, address translation, MOCS and reset. [Existing map](INTEL-DOCUMENTATION-I915-MAP.md) links individual functions at Linux commit 028ef9c96e96197026887c0f092424679298aae8. Device tables and related-generation manuals are evidence for a design, not a substitute for target-specific errata, initialization and actual validation.

Keep address translation and memory ownership, forcewake, scheduling ownership, cache/TLB visibility, completion and recovery as explicit prerequisites. GPU API support and media codecs additionally require their own user-space and kernel interfaces; Intel's advertised features do not establish a working native driver. Previous project reset evidence is recorded in [BCS reset design](BCS-RESET-DESIGN.md); it does not establish command execution. No new physical experiments were performed.
